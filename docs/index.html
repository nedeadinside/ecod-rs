Install

Requires Python 3.12+.

pip install ecod-rs

Quick start

import numpy as np
from ecod_rs import InductiveECOD

rng = np.random.default_rng(0)
X_train = rng.normal(size=(1000, 10))
X_test = rng.normal(size=(200, 10))

model = InductiveECOD(contamination=0.1).fit(X_train)

scores = model.decision_function(X_test)  # higher means more anomalous
labels = model.predict(X_test)            # 1 is an outlier
proba = model.predict_proba(X_test)       # (n, 2): [inlier, outlier]

model.save("model.bin")
model = InductiveECOD.load("model.bin")

ECOD vs InductiveECOD

Both classes have the same interface. They differ in what a score depends on.

InductiveECODECOD
fitSorts every feature of the training data and stores it.Same.
ScoringEach sample is compared with the training data only. Its score does not depend on the rest of the batch.The batch is merged with the training data and every distribution is rebuilt, as in PyOD. A sample's score depends on the whole batch.

In PyOD, fit only stores the data, so its ECOD is always transductive (see PyOD issues #401 and #426). InductiveECOD is the variant PyOD does not have.

How scores are computed

ECOD looks at every feature separately. For a value it asks how rare it is in the left tail (values this low or lower) and in the right tail (values this high or higher), then adds the negative logs over all features. Notation: the training data has n rows and d features, xij is feature j of training row i, and x=(x1,…,xd) is the sample being scored.

Tail probabilities

InductiveECOD counts training values only. One is added to the count and to the total, so a value outside the training range gets a small probability instead of zero:

Lj(v)= #{i:xij≤v}+1 n+1 Rj(v)= #{i:xij≥v}+1 n+1

ECOD counts over Zj, the training values of feature j together with the batch being scored, N=n+m values in total for a batch of m rows. The sample itself is in Zj, so the counts are at least one:

Lj(v)= #{z∈Zj:z≤v} N Rj(v)= #{z∈Zj:z≥v} N

Skewness

The "auto" and "max" methods pick a tail per feature by the sign of its sample skewness. InductiveECOD computes it on the training data at fit, ECOD on Zj for every batch:

γj= m3m23/2 , mk= 1n ∑i=1n (xij−x¯j)k

A constant feature has m2=0 and gets γj=0.

Tail scores

Three sums over features: left tail, right tail, and the tail picked by skewness.

OL(x)=− ∑j=1d lnLj(xj) OR(x)=− ∑j=1d lnRj(xj)
OA(x)=− ∑j=1d lnTj(xj) , Tj= { Rjif γj≥0 Ljotherwise

Tail probabilities are at most 1, so all scores are non-negative. With one tail, a normal sample scores about d on average, because −lnU of a uniform value averages 1. The "max" and "pyod-max" methods give higher numbers on the same data. A sample that sits in the tails of many features scores much higher than any of these.

Score methods

The method parameter picks the final score O(x):

methodScoreWhen to use
"max" max(OL,OR,OA) Default, as in the paper. The maximum is taken over the three whole sums.
"pyod-max" −∑j=1dlnmin(Lj,Rj) Reproduces PyOD's numbers. PyOD takes the maximum per feature, before summing, which is always at least the paper's score.
"left" OL Only unusually low values matter.
"right" OR Only unusually high values matter, for example latencies or amounts.
"auto" OA One tail per feature, the long one.

Scores, labels and probabilities

A fitted model gives three kinds of output for the same samples. All three come from the same score O(x); they differ in what they add on top of it.

At fit, the model scores its own training data once and stores four numbers from those training scores: the threshold, the minimum and maximum, and the mean and standard deviation. predict and predict_proba compare new scores with them.

decision_function

Returns O(x) for every row, nothing else. Higher means more anomalous. This is the output to use for ranking and for metrics such as ROC AUC, since it loses no information.

predict

The threshold t is the 100(1−c)-th percentile of the training scores, where c is contamination. The percentile uses linear interpolation, like numpy.percentile by default. A row is an outlier when its score is above the threshold:

y^(x)= { 1if O(x)>t 0otherwise

So on the training data about a share c of rows is labelled 1. On new data the share can be anything: it is the share of rows that score above the training percentile. contamination does not change scores or probabilities, only this threshold.

predict_proba

Turns the score into an outlier probability p and returns [1−p,p] per row, an array of shape (n_samples, 2) like in PyOD and scikit-learn. Both methods clip p to [0,1]. With Omin, Omax, μ and σ the minimum, maximum, mean and standard deviation of the training scores:

plinear= O(x)−Omin Omax−Omin punify= erf( O(x)−μ σ2 )
  • "linear" maps the training score range onto [0, 1]. Every score above the largest training score gets 1, so it cannot tell a slightly unusual new sample from an extreme one. If all training scores are equal, the range is taken as 1.
  • "unify" gives exactly 0 to every score below the training mean, since erf is negative there. Scores are skewed to the right, so usually more than half of normal samples get 0: 58% in a test on normal noise. Above the mean it rises quickly: two standard deviations above the mean gives about 0.95.
  • σ is the population standard deviation, like numpy.std with the default ddof=0.

predict and predict_proba can disagree

predict uses the contamination threshold, predict_proba does not. A row labelled 1 can have an outlier probability below 0.5, and the other way round. In a quick check with 500 training and 50 test rows of normal noise, predict_proba(x)[:, 1] > 0.5 differed from predict(x) on 4 rows. If you need labels, use predict; if you need your own cut-off, threshold decision_function.

ECOD and the batch

For ECOD all three outputs depend on the batch, because the score does. The same row gets a different score, label and probability when scored alone and when scored together with other rows. The stored training statistics stay fixed, so only the score side moves.

Scoring the training data again with ECOD.decision_function(X_train) gives the same scores as fit: merging the data with a copy of itself doubles every count and the total, so the ratios do not change. These are also the numbers PyOD stores in decision_scores_ with method="pyod-max".

InductiveECOD has none of this: a row gets the same output alone or in any batch.

Methods

fit(x) -> self

Fits the model on x of shape (n_samples, n_features) and returns the model itself, so calls can be chained.

decision_function(x) -> ndarray

Score of each row, a float64 array of shape (n_samples,). See decision_function.

predict(x) -> ndarray

Label of each row, 1 for outliers, an int64 array of shape (n_samples,). See predict.

predict_proba(x, method="linear") -> ndarray

[inlier, outlier] probabilities of each row, a float64 array of shape (n_samples, 2); method is "linear" or "unify". See predict_proba.

save(path, *, compression_level=None)

Writes the fitted model to a file. See Saving and loading.

load(path, *, n_jobs=1) -> model

Static method. Reads a model saved by the same class.

For every method that takes x, it must have the same number of features as the training data.

Input data

  • A 2-D numpy float64 array is read in place, without a copy. Non-contiguous views such as slices and transposes work too.
  • Other dtypes and lists of lists are converted to float64 first, which costs a copy.
  • Values must be finite: NaN and inf raise ValueError.
  • Results are returned as numpy arrays, as in scikit-learn.

Parallelism

n_jobs sets the number of threads for fit, decision_function, predict and predict_proba.

  • 1 (default): one thread. Good for small data, and when the model already runs inside parallel code such as GridSearchCV(n_jobs=-1) or joblib.
  • 0: all cores.
  • n > 0: n threads.
  • Negative values raise ValueError. -1 does not mean all cores here, unlike in scikit-learn.

Scores are bit-identical for any n_jobs. Each model keeps its own thread pool for its lifetime. The GIL is released during computation, so Python threads can run other work in parallel.

On 100,000 rows and more, all cores are 4 to 7 times faster than one thread. Around 10,000 rows it is about 2 times faster, and for tiny inputs starting the pool in the constructor costs more than it saves. See the benchmark.

Saving and loading

model.save("model.bin")                         # zstd level 3
model.save("model.bin", compression_level=19)   # smaller file, slower save
model = InductiveECOD.load("model.bin", n_jobs=0)
  • The file is the model compressed with zstd. compression_level is a zstd level: higher means a smaller file and a slower save, negative values are faster than the default.
  • n_jobs is not stored in the file: a model saved on one machine can be loaded on another with its own thread count.
  • The model is checked on load. A damaged file raises ValueError or RuntimeError (see Errors) instead of producing wrong scores.

Benchmark

ecod-rs compared with ECOD from PyOD.

Data is random normal noise of several sizes (rows x features) and the classical datasets from ADBench. Each dataset is split 60/40 into train and test. Every measurement runs in a fresh process, times are taken over 5 runs. All tables except Parallelism use one thread: n_jobs=1 for both libraries.

What is measured:

  • fit: training, including conversion from numpy;
  • score: scoring the test part with a fitted model;
  • pipeline: fit and score together;
  • convert: passing data into ecod-rs up to input validation;
  • save and load: writing and reading a model file. The default and compressed variants are zstd levels 3 and 19 for ecod-rs, joblib levels 0 and 3 for PyOD.
